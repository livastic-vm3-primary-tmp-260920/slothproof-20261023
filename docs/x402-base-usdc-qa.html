What a reproducible x402 finding needs

  1. Public 402 response: capture HTTP status and a safe decoding of PAYMENT-REQUIRED from the seller's public endpoint. In x402 v2 this advertises the resource and accepts list; it is not a payment receipt.
  2. Network and asset: distinguish Base mainnet eip155:8453 from Base Sepolia eip155:84532; check the actual asset value, not merely the token name. Native Circle Base USDC contract: 0x833589fCD6eDb6E08f4C7C32D4f71b54bdA02913.
  3. Price and payee: compare the precise amount in six-decimal Base USDC units and payTo against the seller's own documented terms. A seller address need not be the customer's address.
  4. Browser compatibility: compare an unpaid OPTIONS preflight and CORS exposure of PAYMENT-REQUIRED against the request origin. Browser success and server-to-server success are different claims.
  5. Delivery and settlement: separate a payment quote, a verified on-chain transfer, and the actual post-payment resource body. Claim a successful sale only when real source-specific settlement and delivery evidence exists.

Official protocol source: x402 Foundation HTTP transport v2. This is a reproducibility checklist, not a wallet audit or a promise that your seller is solvent.
